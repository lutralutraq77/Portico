# Administrator user, device and connector management

The private dashboard can create, rename and revoke user, device and connector records. Each operation displays its exact target and effect before a fresh native security-key approval. New identifiers and enabled state are server-owned. Device creation requires an enabled owner, explicit platform and future authorization expiry; connector creation records the version as `unreported`. Creating a record does not create enrollment credentials, device grants or connector hosting permissions.

The existing policy preview/challenge/confirmation path stores the immutable operation, binds it to the current policy revision and authenticated administrator, and consumes the hardware approval once. Confirmation rechecks current authority and target metadata in the transaction that commits the mutation and audit record. Rename preserves the identifier and shows the old and new name. Revocation keeps a disabled tombstone, closes dependent controller sessions and queues connector cancellation. Subsequent authorization and renewal are denied. Destination socket termination remains subject to its separate runtime qualification.

The current administrator cannot revoke their own user or device through this workflow. Connectors serving enabled management resources are also protected. These guards run during preview and confirmation. Re-enabling tombstones, changing device ownership and deleting records are not exposed by these operations.

The interface validates the preview's operation, exact identity, name, device owner/platform/expiry, connector version and revision. Paged device-owner choices preserve unsent form values. Cancellation or navigation aborts pending browser credential requests; a lost confirmation is reported as uncertain without automatic retry. Names are rendered as text. No invitation secret or credential is added to these record operations.

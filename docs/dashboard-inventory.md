# Administrator dashboard inventory

Phase 7 includes this metadata inventory API and a [private inventory interface](dashboard-interface.md) undergoing browser qualification. Secure browser/device-key delivery, bootstrap UI, the remaining management workflows and full accessibility qualification remain open. Phase 8 requires the owner's approval after Phases 6 and 7 are complete.

`POST /api/v1/admin/dashboard/inventory` uses the existing private administrator HTTP server. The server requires actual TLS 1.3 administrator proof, an active registered administrator/device/user, exact Host and Origin, JSON POST, strict field decoding and `Cache-Control: no-store`. Certificate identity is rechecked in the same database transaction as the read, including on reused connections. Ordinary device and connector servers cannot serve this route. An emergency deny returns no inventory.

The request contains `Section`, `Limit`, optional `After` and `PolicyRevision`. Sections are `users`, `devices`, `connectors`, `resources`, `enrollments` and `certificates`. Pages contain at most 50 records, ordered by ID. `Next` is the last returned ID when another row exists. A continuation must echo the observed policy revision; a changed revision requires a refresh. SQL text comes from a fixed allowlist with bound cursor/limit parameters. Each read has a five-second context, and the existing HTTP response cap rejects an oversized response before writing its body.

The response includes observation time and policy revision. Resources contain only the current revision. Enabled flags and credential dates describe stored configuration; they do not promise effective access or live connector health. Policy previews and mutations continue through the existing hardware-approval handlers.

Dedicated response types and explicit SQL columns omit invitation secrets and hashes, CSR/certificate blobs, factor credentials, keys, pending challenges and approval state before serialization. There is no secret-reveal flag or generic database-table endpoint. Enrollment rows expose lifecycle metadata only. No new schema, cryptography or dependency is introduced.

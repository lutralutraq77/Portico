# Daemon cancellation during a health check

An explicit shutdown could occasionally produce `Local agent daemon failed` instead of the successful stop message. The supervisor selects between cancellation, server completion and a periodic health check. If it selects the timer just before cancellation, the manager correctly removes authority but returns the same unhealthy result used for a failed boot-clock observation. The supervisor then incorrectly reports ordinary cancellation as failure.

The manager now distinguishes requested cancellation from a sticky clock or closed-state failure. The supervisor still stops gRPC and joins its server and handlers before returning; the outer daemon still joins session and loader work and cleans up the protected socket. A clock failure remains an error even if cancellation occurs concurrently. Unexpected server exit still fails. No unlock, authorization, expiry or cleanup deadline changes.

The deterministic regression holds the manager lock until an unbuffered timer send proves that the supervisor selected the health branch, then cancels the context before releasing the lock. It failed on the original behavior with `local agent operation rejected`; the three other ordering controls passed. With the correction, all four ordering cases passed under the race detector.

# Private administrator inventory interface

The private administrator server now embeds an inventory interface at `/admin`, with local `/admin.css` and `/admin.js` assets. It presents users, devices, current resource revisions, connectors, enrollment status and certificate metadata. The layout uses Material 3 surface, color, shape and typography roles, with desktop navigation, mobile reflow, light/dark schemes, visible keyboard focus and a skip link. Configuration is explicitly distinguished from effective access and connector health.

Every asset request requires an actual TLS 1.3 administrator peer and rechecks the current registered certificate, device and user in the controller. A reused connection cannot bypass revocation or emergency denial. Exact Host and path allowlists reject query strings, encoded paths, request bodies and ranges. Top-level GET navigation may omit Origin; a supplied Origin must match exactly. Browser Fetch Metadata, when present, must indicate a direct navigation or same-origin request. Device/connector profiles never serve administrator assets.

All responses use `no-store`, `nosniff`, no referrer and no framing. The content security policy allows only same-origin scripts, styles and connections; inline code, external resources, forms, objects and framing are absent. Static assets contain no deployment state. The page has no credential input, cookies, browser storage, service worker, external font or analytics. Actual identity key handling remains the responsibility of the separately qualified administrator delivery path.

JavaScript calls the [bounded inventory API](dashboard-inventory.md) with exact same-origin JSON POST requests. Each section renders at most 50 rows with revision-bound next/previous pages. Navigation aborts previous requests and ignores late responses. Refresh starts a new revision snapshot. Failures clear previously displayed records and disable pagination. Hiding or leaving the page clears its inventory, and returning requires a fresh read. API metadata is assigned using DOM text operations, never HTML parsing. Unexpected response fields/types are rejected.

`TestDashboardAssetsAuthenticatedAndNonMutating`, `TestDashboardAssetsRejectHostileRequestsAndLiveRevocation` and `TestDashboardAssetsProfileIsolationAndEmergency` exercise the actual private TLS server. Together with the four inventory and three policy HTTP regression tests, these passed the native race detector on 2026-09-12 (141.000 seconds). Native and Linux vet/staticcheck and JavaScript syntax checks passed.

The actual browser fixture passed on 2026-09-12 in 65.23 seconds, using Edge 152.0.4191.66 and Playwright 1.62.1. It verified all six sections, revision-bound forward/backward pagination, hostile metadata as text, keyboard/skip-link navigation, mobile reflow and touch targets, empty browser storage, same-origin requests, network-failure clearing/recovery and live administrator revocation. Desktop, 360px mobile and dark-scheme screenshots were inspected. The first run passed its functional assertions but failed process cleanup; its screenshots also exposed a narrow mobile caption. The corrected harness explicitly closes stdin, and a new caption-width assertion verifies the layout fix. The successful log and screenshots remain under `E:/Portico/work/reports/dashboard-browser-cleanup`; [structured evidence](phase-7-interface-evidence.json) binds the tested source files and artifacts. These are browser component results, not full accessibility or physical custody qualification.

The opt-in `dashboardbrowser` Go build tag adds `TestDashboardBrowser`, which launches `scripts/test-dashboard-browser.cjs` against a real controller with disposable identities and database state. It requires absolute `PORTICO_BROWSER_NODE`, `PORTICO_BROWSER_EXECUTABLE` and `PORTICO_BROWSER_REPORT` paths and a Playwright installation available through `NODE_PATH`. Source `scripts/env.ps1` first so temporary profiles and reports remain on the selected work drive. The harness uses an exact-host loopback CONNECT fixture and process-only `NODE_EXTRA_CA_CERTS`; it does not change host DNS or install a trust root. Browser client-certificate presentation uses Playwright's TLS proxy and ephemeral software credentials, so this test cannot qualify hardware custody or the production native bridge.

This interface is one Phase 7 component. Secure bootstrap, complete management and effective-access approval workflows, overview/audit/security views, the native administrator bridge, physical keys and full accessibility qualification remain open. No canonical acceptance scenario or complete phase is claimed.

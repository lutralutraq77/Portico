# Durable local state

The Linux `internal/localfile` layer reads protected configuration and creates immutable private state files. It requires canonical absolute paths, walks directories using anchored `O_NOFOLLOW` descriptors, and requires root or effective-user ownership with no group/other directory write permission. The host administrator and effective user remain trusted. Shared temporary directories, including sticky directories, reject.

`Create` writes a fresh exclusive 0600 temporary inode, flushes and closes it, then publishes it using `RENAME_NOREPLACE` and flushes its containing directory. It never replaces an existing regular file, link, directory or FIFO. Unsupported filesystem operations fail without falling back to overwrite or weaker publication. A failure after publication leaves the complete file in place. Callers must not delete it or regenerate a key/attempt to retry.

`ReadDurable` validates the same protected path and singly-linked bounded private regular file as `Read`, then flushes both the file and its parent directory before returning bytes. This allows reconciliation after an ambiguous final directory sync. If durability cannot be established, no bytes are returned to authorize dependent network work. Existing protected parent directories must be provisioned durably by the installer; this layer does not create or change their ownership or modes. Successful fsync is the filesystem's durability contract, not proof against defective storage hardware.

The layer does not encrypt its input. The enrollment state owner must supply encrypted data and keep the original key/attempt across network failures. Platform keystore custody and isolation from other processes running as the same user remain separate requirements. Non-Linux operations fail closed.

The initial implementation passed a focused NIC-less Linux guest run on 10 September 2026, using the standard guarded guest setup with a custom init that executed only the localfile package. The cases exercise actual Linux syscalls, 16 simultaneous creators with one winner, preservation of existing inode/content, unsafe paths, a real `O_PATH` directory-sync failure after publication, subsequent durable reconciliation and protected guest path traversal. The final marker was `PORTICO_LINUX_LOCALFILE_FOCUSED_PASS`; the log SHA-256 is `4fd7c0f7279ecf45323a2d358e544c8caad3a9aa114947e85d7d732b46010df4`. Source and init snapshots are retained under `work/reports/phase-6-enrollment-resumed/localfile-durable`. Windows fallback tests and documentation/whitespace checks passed separately. This focused run is not the complete runtime suite or a physical power-loss drill. Final-source native race/full guest CI remains required.

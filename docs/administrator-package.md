# Native administrator development package

The Linux administrator runtime now has a deterministic installation-tree builder and an Arch package recipe. These are unsigned development artifacts. Supported release signing, full browser dependency review and update custody remain separate gates. The package installs no keys, certificates, configuration, accounts, services or network settings.

`scripts/prepare-admin-package.ps1` requires a clean source checkout and the existing pinned Electron Linux archive. It records the complete source revision, source timestamp, upstream archive digest, generated tree digest and recipe digest under the selected work directory. Existing output is preserved. On the developer workstation that directory remains on E:.

`tools/adminbundle` hashes the complete input archive and reads its entries through the same open file. It rejects traversal, absolute paths, ambiguous separators, duplicate entries, file/parent collisions, symlinks, special files, excess depth/count/size and missing essential runtime files. It verifies each ZIP member's length and checksum while streaming it into a new gzip/tar file. Only the three shipped application modules and fixed `/usr/lib/portico-admin` runtime members are emitted. All members use deterministic root ownership, modes and timestamps. There are no package hooks or arbitrary archive extraction onto the developer filesystem. The upstream `LICENSE` and `LICENSES.chromium.html` remain alongside the runtime.

The ordinary runtime executable and crash helper use mode 0755. The exact root-owned `electron/chrome-sandbox` uses 4755, matching the sandbox-helper boundary already enforced by the [administrator command](administrator-command.md). Other application/runtime files use 0644 and directories use 0755. This privileged helper is part of Chromium's Linux sandbox design; it does not grant the renderer Portico's device key. Electron's [sandbox documentation](https://www.electronjs.org/docs/latest/tutorial/sandbox) describes the process boundary, while the existing native transport limits the renderer to the owning frame and fixed administration origin.

## Independent checks

The Arch fixture builds the package as an unprivileged user in the existing digest-pinned build image, without network access. A separate disposable container checks installation ownership and modes, absence of links/writable members, package integrity, removal and preservation of a private owner-state marker. Runtime dependencies remain declared in the recipe. This offline packaging fixture deliberately omits their installation and does not execute the browser; [pacman's documented double `--nodeps`](https://man.archlinux.org/man/pacman.8.en) is confined to that fixture. It is not a user installation instruction or evidence of working Arch desktop dependencies.

The actual installed-window fixture runs separately on the isolated Ubuntu CI runner with desktop dependencies. It installs the verified tree at the fixed production paths and the compiled CLI at `/usr/bin/portico`, refuses to overwrite an existing installation, and runs as an ordinary user. The test uses the unmodified CLI, the shipped `main.cjs`, an actual encrypted administrator key, a private controller, the normal secret pipe and the real read-only kernel clock-health check. It supplies no test entrypoint, debug port, preload or clock override. It waits for successful delivery of every dashboard asset and authenticated inventory, then verifies the private state lock, signal cancellation, lock release, unchanged encrypted identity and audit integrity.

The installed test uses isolated authority/model fixtures. It does not prove physical hardware-key custody, a complete owner-bootstrap/recovery ceremony, physical suspend, production issuer custody, package signing or a fully reviewed distribution. Earlier native virtual-key tests remain the separate evidence for hardware-approval protocol and browser interactions.

Local builder tests pass three tests and 15 hostile/archive subcases under the race detector. Hosted source `1ccbe15` also passed the builder, native virtual-key suite, Arch build/install/remove and actual installed-window test. The installed command passed in 5.33 seconds using the real kernel clock; Arch verified 86 package files with zero alterations before removal and state preservation. The published archives, embedded CLI/tree/recipe/package hashes and equal source/merge trees are verified in [package evidence](phase-7-administrator-package-evidence.json).

Earlier failures remain recorded: a public runtime download returned HTTP 504, the unprivileged builder could not read the initial mode-0600 public archive, and the minimal Arch image excluded the development notice. Bounded public-download retries, explicit read permissions on newly generated public package inputs and an exact fixture-only notice exception corrected those failures. The successful run retained signature policy and private-state permissions. It does not establish physical keys, Arch desktop dependency execution, supported release signing or phase completion.

## Complete scenario and oracles

The guest entry keeps an independently authorized TCP echo stream alive while exercising these boundaries:

- Enrollment uses a real signed P-256 CSR and an ephemeral X.509 fixture CA. Truncations, eight signature-bit mutations, concatenated and oversized DER, and signed subject/SAN/extension claims all reject. Each rejected reservation is followed by actual issuance and certificate-retrieval attempts. Durable state stays unchanged and the signer is never called. The same invitation then accepts its valid CSR and signs exactly once. This checks the controller enrollment/provider boundary; it does not claim deployment or physical issuer custody.
- Real authenticated policy HTTPS receives duplicate fields with identical values, lowercase and escaped aliases for every authorization field, nested arrays, trailing JSON, oversized JSON, actual gzip data expanding beyond 64 KiB, compressed bytes without an encoding header, and an unsupported encoding. All 18 requests return the fixed bounded denial, no-store headers, no canary reflection and unchanged durable state. Valid authorization and close succeed before and after this corpus. These policy and enrollment subfixtures have separate stores; the independent workload additionally stays usable around them.
- A small synchronous peer authenticates with the connector's actual TLS certificate, verifies the carrier root/SPKI and h2 ALPN, then sends HTTP/2 HEADERS and gRPC envelopes directly. Nine mutations cover empty/malformed protobuf, unknown fields, truncated messages, oversized and maximum 32-bit lengths, missing/unsupported compression and an invalid compression flag. Exact non-success gRPC statuses, expected admission counts and released relay state are required. The unsupported compressor rejects in gRPC before Bind; the other eight reach the authenticated handler. No workload permit or destination is created.
- Eight waves each send real RST_STREAM(CANCEL) frames after authenticated headers, a partial gRPC prefix and a valid waiting Bind. Initial SETTINGS exchange is drained; a new SETTINGS acknowledgment provides an ordered barrier after each reset. Every handler, waiting binding, endpoint, watch and tracked worker returns to baseline within two seconds, before five-second hello/RPC and thirty-second pair timeouts can mask missing reset handling. Valid Bind enters the real queue before and after the corpus on the same TLS/HTTP2 connection. These are finite fixture observations, not production Q05 timing acceptance.
- Fifteen malformed workload opens traverse actual paired carrier streams and authenticated inner TLS: zero/oversized/maximum lengths, truncated header/body, trailing JSON and nine duplicate/alias fields with otherwise valid values. They return no READY or application data, explicitly deny at the server and join the carrier workers. Truncated inputs are completed with actual TLS EOF; a local read timeout cannot qualify denial. Authority, destination and application-byte counters remain unchanged.
- Seven malformed DATA/FIN/ACK cases follow valid opens: unknown kind, empty/oversized/maximum DATA, nonempty FIN/ACK and ACK before FIN. Each valid open deliberately creates one session and destination. Its malformed payload forwards no application bytes, creates no additional authority and closes its owned stream. The independent anchor remains usable after every case.

There are exactly eight deliberately authorized destination connections: the anchor and seven valid opens preceding malformed payloads. All eight close with receipts. Only the anchor's expected echo bytes reach the destination. Final workload/client/relay state has no owned streams, waiting bindings, endpoints, watches or workers. Destination sockets run only after the Linux marker/interface guard in the NIC-less guest; host tests never dial the fixture destination. Hosted Windows/Ubuntu execute the control/CSR/HTTP2 component entry and explicitly skip the guest destination entry.

The peer limits incoming HTTP/2 frame size, decoded headers, response frame count/bytes and operation duration; it owns no reader goroutine. Errors must not contain its private fixture canary. The policy API rejects Content-Encoding rather than decompressing bodies. Continuous mutation coverage additionally comes from the existing seven fuzz targets, including real CSR/DER, strict JSON, protobuf and workload framing decoders. Finite corpus and fuzz observations do not prove absence of all parser bugs or whole-process memory exhaustion under arbitrary traffic.

Protocol references: [gRPC HTTP/2 envelope specification](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-HTTP2.md), [RFC 9113 reset and closed-stream processing](https://www.rfc-editor.org/rfc/rfc9113.html#name-rst_stream). The exact gRPC status expectations follow the pinned v1.83.1 serverStream.RecvMsg and compression handling: parser failures can write transport status before the handler's generic PermissionDenied.

# Phase 6 encrypted enrollment command evidence

The development Linux command now prepares an encrypted local P-256 key/attempt, redeems the approved invitation, retains the exact public certificate and activates it using fresh TLS. Each stage can run in a separate process. A lost response retains the original attempt; the client does not regenerate or overwrite it. The [command contract](enrollment-command.md) describes approved public configuration, the dedicated inherited secret pipe and storage limits. ## Remaining scope

This is encrypted software-key storage with the OS user and administrator trusted. It does not provide hardware custody, same-user IPC isolation, forensic erasure, physical crash/power-loss qualification or a desktop unlock experience. The resource client still uses its earlier identity loader; connecting the encrypted identity to resource access is next. An installed enrollment/controller/connector service, Arch packages, Windows/Android integration, actual administrator keys/hostname/recovery, independent networking, signed distribution and the rest of the fifteen-phase objective remain required. Seven canonical acceptance cases remain implemented and 84 planned; none is promoted here.

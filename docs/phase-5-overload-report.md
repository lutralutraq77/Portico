## Reproduced failure and runtime correction

The initial slow-destination scenario canceled a client whose writer was already backpressured. The server's framing worker was blocked delivering previously received DATA, while its forwarding worker was blocked on destination TCP. Reading transport EOF through those workers could not terminate the session; valid control renewals could keep it alive. The initial guest run failed its server cleanup assertion. A separate regression then failed on both client and server before the fix: a real in-memory framed DATA transfer remains unconsumed, the carrier terminates, and a valid future lease cannot excuse retained supervisor/framing work.

The existing client and server supervisors now also select the carrier's independent Done signal and close the workload's owned handles/context. This adds no polling loop or worker and preserves the existing lease/clock checks and FIN acknowledgment contract. The regression passes after the change. The supported carrier emits Done after its own workers join. [Client supervisor](../internal/workload/client.go), [server supervisor](../internal/workload/session.go), [regression](../internal/workload/runtime_test.go).

The first corrected guest run passed the server-worker closure check and the controller-initiated unread-client closure case. Its slow-destination fixture still failed while draining previously queued TCP data through an artificially reduced receive window. The final fixture keeps the reader stopped during backpressure and uses the normal receive window afterward; it still requires observed peer closure and joined destination work. Both unsuccessful runs and their exact source hashes remain archived separately. No failed run is relabeled as passing.

## Complete PROTO-05 scenario

The [executable scenario](../internal/controller/workload_overload_linux_test.go) has five subcases, all using actual control HTTPS, carrier TLS/gRPC, inner TLS and destination TCP in the guarded NIC-less Linux guest:

- A stopped destination reader backpressures the client's producer. A client close must join the producer and server forwarding workers before the fixture resumes reading queued data; the destination then observes peer closure. Independent traffic survives.
- An unread client backpressures the destination's producer. The connector closes only that session through authenticated controller control. The resource stays valid, so ongoing resource checks cannot substitute for client observation of the terminal carrier. All producer/stream/destination work joins and independent traffic survives.
- Two live sessions saturate the global workload quota. Eight batches each prepare three additional carrier pairs over fresh outer TLS connections before attempting workload opens. All 24 excess opens fail at the workload boundary, with no new authorization, destination or displacement. A fresh session succeeds after the holders close.
- The same 24-open exercise saturates the per-device limit of two while the separate global limit is eight. The five simultaneous workload attempts cannot hit the global ceiling. Denied opens leave both live sessions and durable authorization count unchanged; capacity recovers afterward.
- A three-worker connector runtime sustains eight reconnect waves. One session remains usable throughout, while two other sessions repeatedly transfer distinct multi-frame payloads and close or abandon their carrier. Later waves use fresh device TLS connections. Four simultaneous raw authenticated Dial requests per wave must receive explicit server PermissionDenied after identity admission, with no waiting binding or extra destination. All 17 session IDs are distinct; every session has a closure receipt and all stream/runtime workers join.

Each backpressure producer reuses one 32 KiB buffer while attempting a 64 MiB total transfer. It must make real progress and then remain stalled below an 8 MiB observed buffering ceiling before cancellation. The focused run stalled at 3,080,192 request bytes and 786,432 response bytes. This exercises backpressure rather than merely limiting the test's input allocation. The workload's fixed 32 KiB DATA/copy buffers, synchronous application pipes, unbuffered relay delivery and configured HTTP/2 windows bound the relevant buffering path. Previously queued TCP bytes may drain after closure; the test does not claim they can be recalled.

Capacity samples include pending closure receipts, relay streams/waiting bindings/endpoints/watches/workers, outer connections and client ownership. Quota runs reached eight simultaneous outer connections, ten carrier stream endpoints and twenty tracked relay workers. The final sampler observed one waiting binding during the direct quota tests and three in the runtime test, below the configured per-connector ceiling of eight. The per-device run can contain five global workload records during authentication while only its original two device sessions obtain authority. Explicit post-cancellation zero-state checks and fresh successful sessions reject retained capacity; the separate continuous runtime scenario checks independent traffic and payload integrity after each wave. These are finite fixture observations, not production throughput or Q05 acceptance.

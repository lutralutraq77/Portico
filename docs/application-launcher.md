# Linux application launcher

`portico agent exec` gives an explicitly selected local application a private Unix socket bound to one exact resource ID and revision. The agent must already be unlocked. The endpoint's parent must already be a protected directory owned by the current user with mode 0700; the socket is created with mode 0600 and removed during normal cleanup. An uncatchable launcher crash can leave a stale endpoint; startup rejects existing entries, so recovery requires the owner to verify that the old process is gone before removing its stale socket. Accepted peers undergo the existing kernel UID check before any resource handler starts.

The command shape is:

```text
portico agent exec --socket /run/user/1000/portico-agent/agent.sock --resource UUID --revision N --endpoint /run/user/1000/portico-app/resource.sock -- /absolute/program arguments {socket}
```

The executable must have a canonical absolute path. Each standalone `{socket}` argument becomes the specified endpoint. Other arguments are literal; no implicit shell, variable expansion or PATH search is performed. The command permits at most 64 arguments and 32 KiB of argument data. Standard input/output/error are inherited as files, with no application data copied through Portico's diagnostic output. Portico errors stay fixed; the selected application controls its own output. This uses the standard [Go process API](https://pkg.go.dev/os/exec#Cmd).

Every accepted connection uses the existing [resource-stream RPC](agent-resource-streams.md), including fresh remote authorization, no input consumption before READY, independent input/output FIN and final status. The local connection cannot choose a destination or override its resource revision. Output EOF does not prove successful forwarding: the launcher joins the application's direct child and all accepted stream workers, returning failure if any of them fails. At least one stream must succeed. Bytes already read by the application cannot be recalled after a later error.

There are six active stream slots plus at most one connection held by the acceptor before admission. Exceeding admission stops the invocation and its streams. Slots remain occupied until their workers have finished. Application exit closes new admission and allows at most five seconds for accepted streams to finish. Context cancellation or a failed/expired suspend-aware fifteen-minute clock window closes the endpoint and streams and terminates the direct child. The clock is also checked before each admission and before successful return. The selected executable and other processes with the same UID retain their ordinary OS permissions; this launcher does not sandbox them or intercept their other network traffic. No descendant-process containment is claimed.

Programs that support Unix transport can use this endpoint while keeping their application protocol and authentication. For example, curl supports [HTTP through a Unix socket](https://curl.se/docs/manpage.html#--unix-socket). Its real HTTPS URL and normal certificate verification must remain in force. The current component qualification uses actual Unix client subprocesses and agent RPCs.

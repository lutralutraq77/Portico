# Linux client-agent local transport

`internal/localipc` provides a protected Unix-domain stream for a future per-user client agent. The transport is implemented and has passed focused Linux kernel tests. An agent command, application protocol, installed service and browser bridge are not yet supplied by this component.

`Listen` requires an explicit canonical absolute pathname below an existing directory owned by the effective UID with mode 0700. The shared local-file traversal checks every ancestor through retained no-follow directory descriptors. Root or the effective UID must own ancestors, and group/other writes are rejected. Shared temporary directories and symlink ancestors reject. The listener binds through its retained `/proc/self/fd` directory handle, sets only its new socket to mode 0600, and checks its type, ownership and single link. It changes no process-wide umask or existing directory permissions. Abstract sockets and TCP are not accepted.

An existing entry, including a stale socket, prevents startup. There is no automatic deletion or permission repair. Closing the listener unblocks accept and removes only the captured socket inode through the retained parent descriptor. A renamed ancestor cannot redirect cleanup to a replacement directory; a replacement entry is preserved. A crash can leave a stale socket for explicit operator inspection. Accepted connections remain owned by their caller and must be closed by the application during shutdown.

Every accepted connection must have the listener's effective UID according to Linux `SO_PEERCRED`, before application bytes are read or an application handler runs. `Dial` independently checks the protected socket path, mode and owner; connects through a retained directory descriptor; rechecks the socket inode; and verifies the actual server UID. A changed socket owner does not change the server's kernel credentials. Dial has a five-second connection cap and honors earlier caller cancellation. Its returned connection supports standard Go deadlines and independent Unix-stream half-close. [Linux Unix-domain socket credentials and filesystem permissions](https://man7.org/linux/man-pages/man7/unix.7.html), [Go UnixListener cleanup contract](https://pkg.go.dev/net#UnixListener.SetUnlinkOnClose).

The effective UID and host administrator remain trusted. This does not distinguish applications running as the same user, prevent that user from passing a connected descriptor, or authenticate a browser origin. Kernel peer credentials describe the process at connection/listen time. Filesystem cleanup cannot defend against a trusted same-UID process deliberately replacing an entry between the final comparison and unlink. No claim is made about other operating systems; their adapter returns an explicit unsupported error.

This transport grants no resource permission. The agent protocol must still bound requests, active connections, stream flow control and lifetime, and reuse fresh controller/workload authorization for every resource operation. The pinned gRPC local-credentials adapter identifies a Unix transport but does not itself check peer UID; any use must retain this listener/dial boundary. Q07 remains open for complete application flows and platform qualification, and Q02 remains open for the browser/native administrator boundary.

## Initial qualification

The focused NIC-less Linux guest passed the existing protected-file suite plus the new IPC tests: 24 IPC subcases, including concurrent startup with one winner, full-duplex and half-close transfer, cancellation of blocked accept, preserved existing files/links/FIFOs/sockets, long parent paths, unsafe ownership/modes, symlink/shared ancestors, replacement preservation and cleanup after parent rename. Three cases use real subprocesses under UID/GID 65534 to verify filesystem exclusion, rejection before application acceptance, and actual server credentials despite reassigned socket ownership. The helper's standalone skip is intentional.

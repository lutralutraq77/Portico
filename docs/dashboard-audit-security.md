# Administrator audit and security views

The private dashboard includes Audit and Security navigation. Both use the existing authenticated inventory endpoint, strict request decoding, exact-origin checks and live administrator TLS verification. They introduce no mutation, export acknowledgment, factor enrollment or secret-reveal endpoint.

Audit shows immutable event envelopes in sequence order, oldest first, with up to 50 records per page. It displays occurrence time, actor and target identifiers, event action, sequence and hash. Stable event IDs identify pagination positions; SQL orders by sequence rather than random IDs. An unknown cursor or stale policy revision is rejected. The server reuses the audit chain verifier before returning a page. Verification and reads share the request's five-second deadline; a history that cannot be verified within that bound returns no page. Reading does not advance the durable export checkpoint. Hash continuity alone cannot detect a history rewritten together with its local head; independent checkpoints remain necessary.

Security is limited to the administrator presenting the actual TLS certificate. It shows the user/device names and identifiers, certificate fingerprint and expiry, initial registration deadline, and counts of enabled and tested enabled factor records. Disabled factors and another user's factors are excluded. No credential ID, public-key blob, attestation document, ceremony response, invitation token or private key enters the response. Counts describe stored records and do not establish separate physical authenticators or recovery readiness.

The browser validates exact item fields, dates and safe numeric values. Audit rows must have consecutive sequence numbers and matching adjacent hash links; security responses must contain one identity, a valid fingerprint, a future certificate expiry and consistent factor counts. Invalid responses, policy changes, network failures, hidden pages and administrator revocation clear displayed data. The interface uses text nodes and stores no inventory in cookies or browser storage. Mobile cards and keyboard navigation use the existing accessible dashboard layout.

After adding readable user/device names, the five affected security/audit/secret-omission tests and three subcases passed in 13.483 seconds. Tests compare paginated events with the audit export reader, assert unchanged security/export state, reject altered/deleted events and head corruption, verify owner-scoped live factor counts, and deny reused-TLS reads after administrator revocation.

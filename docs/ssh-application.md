# SSH application adapter — qualification in progress

The development Linux client now has a foreground SSH adapter built on the existing application supervisor. Real OpenSSH integration has not yet been qualified; this page records the implemented boundary and remaining tests. It does not establish supported SSH use, hardware key custody or completion of Phase 6.

The command selects an exact catalog resource and revision, a new protected application socket, the logical SSH host-key name, the SSH account, a known-hosts file and a user identity file:

```text
portico agent ssh --socket /private/agent.sock --resource UUID --revision N --endpoint /private/ssh.sock --host ssh.private.test --user alice --known-hosts /private/known_hosts --identity /private/id_ed25519 -- [remote command]
```

The host name identifies the expected SSH host key. The resource selection determines the connector destination. Remote commands retain OpenSSH's usual remote-shell semantics. No local SSH options are accepted after Portico's separator. The launcher runs `/usr/bin/ssh` with explicit trust and transport options, no user/system SSH configuration, no multiplexing or background mode, no automatic host-key acceptance or updates, and no SSH agent or certificate fallback. User authentication uses the selected SSH identity; Portico enrollment does not authenticate an SSH account. Encrypted SSH keys can use OpenSSH's terminal passphrase prompt. Hardware-backed SSH and certificate issuance are not implemented by this adapter.

The adapter uses [OpenSSH descriptor passing](https://man.openbsd.org/ssh_config#ProxyUseFdpass). OpenSSH starts a fixed proxy command that expands a quoted child-only environment value to the current Portico executable. Host names and paths are not inserted into shell command syntax or OpenSSH percent expansion. The helper checks that its output is a Unix stream whose actual peer has the same effective UID, then connects using Portico's protected local socket validation. It sends one connected descriptor and exits. Pipes, TCP, Unix datagrams, Unix sequenced packets and other-UID recipients reject before endpoint dialing. Sending is bounded and cancellation closes and joins owned work.

Descriptor delivery grants no independent authority. The application supervisor continues to own the accepted resource stream and its final RPC result. Success requires SSH process success, a successful resource stream and successful final status for every accepted stream. A remote error, failed authorization, cancellation or failed final status returns failure and joins the direct child and stream workers. The same fifteen-minute process window, six-stream bound and five-second completion drain apply as for `agent exec`.

The new adapter does not change host DNS, routes, firewall rules, services or trust files. OpenSSH remains an ordinary trusted local application with the user's OS permissions; this is not an application sandbox. Known-hosts and identity paths must be canonical absolute paths without OpenSSH expansion tokens, quoting characters or line breaks. Users remain responsible for provisioning the correct SSH server trust and user credentials in protected locations. All non-Linux entry points reject.

The initial NIC-less Linux run passed direct and actual CLI descriptor transfer, exact binary data and half-close after helper exit, invalid recipient denial, blocked-send cancellation, existing application supervision, SSH argument validation and environment replacement. Its other-UID child failed in fixture setup because it attempted to read the root-only isolation marker. The guarded parent now establishes that precondition before dropping the child's UID; the negative child independently creates its own protected endpoint to observe whether a rejected recipient caused any dial. The corrected run passed all six top-level tests and 40 subcases, with no failures or skips. Native race checks passed 23 top-level tests and 89 subcases; final CLI race checks passed nine top-level tests and 44 subcases after adding the new two-argument helper to the fuzz oracle. Bounded CLI fuzzing passed 13,160 executions. Windows and Linux vet/staticcheck passed after placing Linux-only configuration helpers in their platform-specific file. The final Linux run repeated all six top-level tests and 40 subcases on that final source and passed; prior results remain separate. See the [source and artifact evidence](phase-6-ssh-descriptor-evidence.json). The initial failure is retained at `E:/Portico/work/reports/ssh-descriptor-linux/runtime`.

`TestArchGuestApplicationSSH` now exercises an actual OpenSSH client against a real SSH protocol destination through encrypted enrollment, the restricted issuer, agent, controller and connector. Its 16 subcases cover host-key and user-key rejection, explicit trust-file selection, an ambient SSH agent and default-key fallback controls, exact resource selection, remote exit status, remote option spelling, lock/re-unlock, live revocation, cleanup and unchanged identity/network state. HTTPS shares its enrollment setup and retains its existing regression cases. Compilation, vet and staticcheck passed; these new runtime tests have not yet passed.
